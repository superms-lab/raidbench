What should I verify before continuing after a major update?

Direct answer

Read the current official announcement, list every changed system your plan depends on, and test those dependencies before spending or moving important assets. Preserve the old plan until the new behavior is confirmed in the intended scenario.

Decision signalWhat to verifyNext move
Patch affects a dependencyMap the change to build, base, or scenarioTest the affected layer first
Migration changes accessConfirm character and server eligibilityAvoid irreversible moves based on old rules
Performance appears differentRepeat the same controlled activitySeparate patch impact from changed conditions

Decision checklist

  • Read the latest official update and bug-fix notices
  • List changed systems used by the current plan
  • Record important character, inventory, and base state
  • Test one affected dependency in a low-cost activity
  • Update the plan only after the result repeats

Stop and recheck when

  • Stop when the official note does not cover an irreversible transition
  • Roll back the planned investment when the core interaction is unverified

Common mistakes

  • Changing the complete build from patch headlines
  • Assuming old scenario rules still apply
  • Using community speculation as confirmation of carryover
